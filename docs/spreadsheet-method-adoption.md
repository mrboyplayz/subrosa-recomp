# Spreadsheet Method adoption for the C client

Source: `C:/Users/junin/Downloads/THE-SPREADSHEET-METHOD.json`, version 1.0.
This is an incremental adaptation of sections D1–D7, 6, 7.3, 8.4, 8.6,
14, and optimizations O1, O2, O12, O16. Project decisions are recorded in
`sheets/decisions.tsv`. The current target remains vanilla Windows C.

## Canonical book

- `00-doctrine.tsv`: target identity, pinned binary, scope and tool versions.
- `01-schema.tsv`: typed columns and enum domains.
- `02-plan.tsv`: 4,269 recognized export entries plus 20 recovery helpers;
  stable IDs, native addresses, current symbols, evidence and module owners.
- `03-impl.tsv`: implementation observations; refresh preserves status and
  evidence. Importing a body never promotes it to verified.
- `kernel.tsv`: allowlist of recovery scripts, native algorithms, layouts,
  tests and glue, with available test paths.
- `work.tsv`: current recovery priorities and their function references.
- `tokens.tsv`: unavailable provider token measurements are explicitly NULL.
- `decisions.tsv`: deviations for this existing C project.
- `abi.tsv`: evidence-backed signatures applied to Ghidra; currently the
  scene raycast Boolean result and its three input parameters.

Run `python scripts/client_sheet_book.py preflight` for structure, schema,
types, domains, key uniqueness, evidence paths, work references, kernel
allowlist, export-address coverage, plan/implementation divergence and the
pinned executable hash. `--strict` also fails for unverified implementation
rows. No imported row is currently accepted as complete behavioral parity.

`python scripts/client_sheet_book.py refresh` refreshes implementation
observations. Edit planned ownership in the TSV; the production source
splitter reads that ownership and rejects unindexed functions. Preflight
runs before source splitting and thus before the prepared client compiles.
Every generated output remains in ignored `work/` or `reports/` directories.
Unchanged generated bytes preserve timestamps.

## Limits of this first adoption

The book indexes recognized functions and the recovery tooling. It is not
yet a total inventory of executable bytes, asset records, data aliases,
types, indirect targets or every gameplay scenario. Existing manifests,
audits, native differential fixtures and raw analyzer exports retain their
evidence role. Constants and algorithms are not being replaced by guessed
spreadsheet descriptions. Whole-function verification remains separate
from compilation, linkage and isolated native comparisons.

Rust and Bevy game generation remain deferred. At the user's request,
ghidra-cli 0.2.2 is installed at `C:/Users/junin/.cargo/bin/ghidra.exe`, built
from akiselev/ghidra-cli commit `10019ba1f3b54c9edcca8ec644a30e16fb7b7c79`.
Rust 1.99.0 with the Windows GNU target is installed for this recovery tool.
The CLI uses the existing Ghidra 12.1.3 and JDK 25 installations. All doctor
checks pass (`reports/ghidra-cli-doctor-20261003.txt`). Its separate project
is `re/ghidra_projects/subrosa-vanilla`, avoiding the GUI project's lock.
No throughput claim or under-ten-hour completion claim has been established.
