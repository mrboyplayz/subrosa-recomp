Practice now defaults to `debugtest` in both the maintained C recomp and the
Rust desktop client. This deliberately small debug arena uses shared native
SBC/CSX files generated by `scripts/create_test_map.py`.

The floor is 64 by 64 metres at y=24, with boundary walls and four separated
orange boxes. The player spawns in the clear centre at x=z=1024. The C client
creates one human and skips the normal Practice items, vehicles and trains.
The Rust client loads the same cells for its visible mesh and collision.

Install or regenerate the arena from the decompilation directory:

```powershell
python scripts/create_test_map.py
```

To load the city again, launch Rust with `--map test2`, or set the C launch
environment variable `$env:SUBROSA_PRACTICE_MAP='test2'`. Clear that variable
to restore the test arena default. The original game's executable and existing
map files are untouched.

This is a user-requested debugging extension, not original-game map parity.
It isolates map loading and player movement; renderer and active-ragdoll bugs
are still separate recovery work.

Validated on 2026-10-05: the Rust integration fixture probes all 256 ground
cells, the four enclosing walls, and the centre spawn. All three textures load
without missing-resource warnings. The desktop smoke run passed movement,
jump, pause/options/resume and scene cleanup, with about 165 FPS on this PC.
The bounded C launch reached world rendering with four loaded city chunks,
one actor/human, zero vehicles, and the intended pelvis position
`(1024, 25.25, 1024)`. Native spawn-storage and main-menu fixtures pass; the
menu fixture checks the deliberate new map selection separately from native
state parity. These checks do not establish complete C renderer parity or
correct active-ragdoll behavior.
